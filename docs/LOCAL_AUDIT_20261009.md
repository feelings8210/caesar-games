研究日期：2026-10-09。基线：`eb1e11b` / `v2.8.1`。本地分支：`codex/hoops-local`。

## 结论与下一版方向

现有项目已经有可用的训练闭环：看回合、做选择、看结果、理解线索，再练。主要质量差距在于人物仍采用金属棋子美术，人物动作、球和声音缺少共同的事件时间线，球馆也缺少比赛现场的生活感。继续增加光效或关卡数量不会自动解决这些问题。

建议方向：**有 NBA 转播观感、可亲自参与的篮球决策游戏**。先把“突破分球”做成一个完整的代表回合，再扩大到全关卡。NBA 2K Mobile 是设备侧的视觉参考；NBA 2K27 是动作与攻防反馈参考。目标的第一步是球员可信、动作自然、球与手脚接触正确、声音同步，随后增加场馆氛围。

### 已复现，需要优先修复

1. **全局静音没有立刻静音。** 播放教练语音期间点 Sound off，`sounds.isMuted=true`，但 master gain 仍为 0.42，语音源继续播放，最终输出 RMS 仍约 0.096。根因是 `js/engine/sound.js:32` 只更改开关，主要阻止新声音。修复应在总输出控制静音，并处理旧语音的停止策略。
2. **退出后迟到的语音会播放。** QA 延迟一个未缓存语音的 fetch，回到 HOME，再放行 fetch，出现新的语音源与非零输出。`hoops/audio.js:252` 的异步 voice 在解码后没有核对请求是否已取消；`stopVoice()` 只停当前源。需要请求代号，使退出、重试、切换语言能取消旧请求。
3. **重复换场景累积 WebGL 资源。** 同一 10 人场景重建并渲染六次，几何资源计数 306 → 456，纹理 180 → 380，每次约 +30 / +40。`court3d.js:333` 只 remove 人物与圈；号码平面、圈、SkinnedMesh 的私有骨骼纹理等生命周期没有完整释放。应清理每实例资源、停止 mixer、复用角色池，保留共享模型/号码纹理的正确归属；目标是多次换关后平台化，而非错误 dispose 共享数据。
4. **音效触发与落地不一致。** 代表回合七次运球触发中，六次距最近球最低点约提前 132–201 ms，另一次匹配到前一最低点，差约 -267 ms。`runner.js:134` 用独立 60 ms 起点触发，视觉最低点在 400/560 ms 周期中间。这里测的是触发时间与视觉最低点，未测素材声学起音或真机扬声器延迟。
5. **2D 正确目标被另一选项标签遮挡。** `break-stay` 的最佳选项是“突到篮下”，点其圆心却命中覆盖在上面的“急停跳投”标签，选择从 1 变成 2，得到 grade 1。原始和镜像场景均定点复现。`court.js:365` 优先使用 DOM 标签而非目标距离，导致标签争抢点击；需要标签布局/目标命中规则共同修复。canonical smoke 只记录结果，没有断言每轮最佳选择的实际 grade，因此错误未让脚本失败。

原始证据：`runtime-report.json`、可重跑的 `runtime-audit.mjs`，以及 `target-overlap-audit.mjs` / `target-overlap-report.json`。这些问题尚未修复；常规冒烟未有效检查这些预期。

### 画面与动作的具体差距

- 皮肤材质 `metalness=1`，同一人形和固定底座，截图更接近金属人偶。应改皮肤、布料、鞋的独立材质和球员体型，再调整灯光。
- `Dribble`、`DefSlideR` 动作已经在 GLB 中，但 `_pickLoop()` 没有选用。移动持球人仍主要跑 Jog / Sprint；防守人只侧滑左侧，朝向随移动方向，削弱“面对进攻者”的篮球感。
- 上篮、扣篮、跳投全部触发同一个 `Shot`。传球/出手动作与球飞行同时开始，没有统一的离手关键帧；接球声与紧接的投篮 release 在代表回合里仅隔约 0.3 ms。
- 跑位每个 beat 都从零加速再减速，连续行动也逐段缓入缓出；应该用连续速度、急停和转向动作，之后做脚掌锁定与球手接触修正。
- 文字有击地传球，但当前 pass 是空中弧线，仅有 lob 标记；需要 `passStyle` 区分胸前、击地、单手推传、高吊。
- 投进后球进入 floor rest；应增加穿网、落地、后续弹跳，分别表现刷网、打板与打铁。
- 当前有木地板、座椅、灯和背景，但看台为空、重复方块明显；球场仍有展示台边框。应先做可信的场馆比例、层次与转播构图，再加入观众层和 LED。
- 低档目前主要降低像素比、阴影和光柱。同一 DSF=1 场景 high / low 为 322 / 318 draw calls，模型工作量基本保留。真实高 DPI 时降分辨率可能有效，但普通 iPad 还需要人物材质/骨骼/看台层级的实际降档。

## 视觉开发方案

第一版默认风格：现代室内球馆，偏真实的运动员比例，明亮球场与较暗观众席，原创球队配色；用转播构图、材质和动作表现篮球的力量与速度。

| 优先级 | 具体工作 | 验收样本 |
| --- | --- | --- |
| 第一批 | 角色脱离棋子底座；皮肤/球衣/鞋合理材质；后卫、侧翼、内线体型区别；自然手掌与持球姿态 | 同一球员近景 + 实际比赛镜头；错位大小能直接看懂 |
| 第一批 | 建立共用动作时间线：触地、离手、接球、出手、入网事件；启用持球跑与左右侧滑；急停/转身 | 正常速度突破 → 补防 → 分球 → 接投；球不脱手，脚不明显滑动 |
| 第二批 | 场馆比例、木地板粗糙度/反射、篮球架、接触阴影、看台分层、简洁 LED 与观众 | 同一回合的转播全景和近景；空位仍清晰，场景不抢阅读线索 |
| 第二批 | 主场比赛 UI、简洁比分时间、克制回放；决定阶段逐步减提示 | 普通 iPad 上目标易点、全场信息可读，切镜不耽误判断 |

开始时只需要后卫/侧翼/内线的代表体型和一组原创球队外观，不必先做大量球员脸、球馆和服装。观众先用实例化/图集与少量近处动作，避免给每名观众都使用复杂骨骼。

## 声音建议

优先建设清晰、同步、能表达动作力量的声音，然后再听选素材。当前不能独立进行真实听审，以下是结构建议与测量结论，不是“我听过后觉得更好”。

1. **球与鞋是主角。** 按落地力度、脚掌急停、传球离手、接球、刷网、打铁事件发声；小幅随机变化，避免每次完全一样。鞋声由急停/侧滑触发，减少自动定时鸣叫。
2. **分离三层混音。** 近处球鞋保持清楚；球馆声提供空间；教练语音在需要解释时才出现。声音按球场方位与距离改变，但 iPad 小扬声器和 mono 下也必须清楚。
3. **训练与比赛两种声场。** 学习时较安静，挑战时有克制的观众底噪，关键进球再提升欢呼。空看台搭配满场欢呼的视听矛盾要一起修。
4. **语音简短且按需。** 开局一句、结果一句、规则可以点播；语音出现时适度压低其他层，避免连续夸奖叠盖比赛。声音关后即时静音，退出后没有迟到语音。
5. **音乐放在菜单/挑战开场。** 对局先留球鞋声的节奏；音乐风格可试短的 hip-hop 鼓点或竞技氛围，再由 Owner 听 A/B 决定。

五个文件的 FFmpeg 测量存于 `audio-measurements.json`。第 2 关规则中文约 -16.4 LUFS，英文 -19.8 LUFS，差 3.4 LU，说明“所有语音都 -16 LUFS”的文档描述不能直接当作实测。30 秒观众底噪 LRA 13.3 LU，true peak 约 -0.4 dBFS，应检查其稳定性与 MP3 编码峰值。0.35 秒鞋声的 EBU 门限读数不适合解释为音量或“无声”；短 SFX 要结合峰值、起音、最终混音与实际听审。

未来 A/B 要比较完整回合：A 为干净训练声场，B 为比赛声场，两版保持语音可懂和相近最终响度。在普通 iPad / iPad Pro 外放，以及耳机各听一次。生成语音或音乐前按项目媒体生产线与资产库规矩执行。

## 游戏性：保留优点，增加真正的阅读和参与

已有左右镜像、同开局不同防守、弱项加权抽题、时间收紧、战术 Walk、分技能统计；升级时保留这些，避免重新做一套只有问答按钮的课程。

- **两段选择。** 突破看到补防后选择分球；底角接球后防守补回，再选出手、突破或 extra pass。第一选择真的改变接下来的空间与防守。
- **提示逐级减少。** 学习模式暂停、线索圈和解释完整；挑战模式只短暂停；熟练后少提示、连续决策。先检查身体与球的表现足够可读，再提高压力。
- **变体增加篮球含义。** 防守位置、补防时机、剩余时间和角色体型不同；不仅镜像或换颜色。先由教练确认多个答案的条件，允许“可打但不是最佳”。
- **错题延后重练。** 用已有技能统计，在随后短 session 带回相似但未见过的局面，区分记住关卡和学会阅读。现有统计应进一步分别显示正确率和正确选择的速度。
- **简短挑战。** 先试每次 3–5 分钟、若干回合，奖励原创球衣/球馆外观。不要把养成数值变成花钱获得更正确答案。
- **教练验证包。** 从四类阅读各取代表场景，提供最优/可打/错误的完整结果和判定理由；教练确认后再扩展。用未见场景测试理解，之后以真实 3v3 的决策记录查看是否有迁移，避免只报游戏内连胜。

## 执行顺序与完成标准

1. **基础修复。** 静音、异步语音取消、场景资源生命周期、2D 点击目标遮挡；加入能复现这些真实失败的测试，并使冒烟断言实际选择的 grade。连续换关至少 30 次后 GPU 资源不线性增长，静音/退出没有残留输出，最佳目标点击正确。
2. **代表回合。** 只做突破分球，覆盖人物材质、球馆、运球、补防、急停、传接与出手，同步声音，约 20–30 秒可互动完整体验。保留旧版作同回合比较。
3. **双 iPad 验证。** 普通 iPad / Pro 记录型号、iPadOS、Safari/PWA。建议先以普通款持续 30 fps、Pro 持续 60 fps 为目标，先测后定；均做 15 分钟连续回合、后台恢复、离线和静音测试。帧率目标是待验证目标，尚未达到。
4. **扩展。** 代表回合的画面、声音和交互经 Owner 看/听后，再扩到其余 9 关、Read & React 以及战术；之后优先加入第二次决策与错题循环。

如升级需要新模型、动作、贴图、字体或声音，先执行 3090 全局资产库 preflight 与本地检索；仅从受控来源获取，记录许可、来源和 SHA256， canonical bulk 文件留在 3090。此前本轮没有新增资产，也没有将竞品截图转作游戏素材。
