ROOT_CAUSE_CONFIRMED
================================================================

YES.

The v1.1.0 board combined:

  container-type: size
  height: 100%
  width: auto
  aspect-ratio: 600 / 1010

WebKit 2287 resolved that size-contained board to width 0 while preserving its
height. The DOM and game state were healthy (60 stations and 50 pieces), but
all percentage-positioned board content collapsed onto zero horizontal space.

================================================================
BOARD_SIZING_FIX
================================================================

The gameplay mount now owns a positive, viewport-bounded width:

  width: min(44vw, 53vh)
  width: min(44vw, 53dvh)
  aspect-ratio: 600 / 1010

The board fills that resolved mount with width:100% and height:100%.
container-type:size and the board's width:auto sizing dependency were removed.
Replay has an explicitly ratio-constrained mount as well.

This is one cross-browser sizing model. No Safari-specific branch was added.
Piece text uses a viewport clamp instead of board container units. Static
board, piece, and control visibility remains valid without animation.
