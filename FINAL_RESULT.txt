CAESAR GAMES — JUNQI V1 RECOVERY
Build v1.1.0 · rules junqi-v1.1 · schema 3 · 2026-07-28

================================================================
ROOT_CAUSES_FOUND
================================================================

RC1  Owner-reported mode switch failure.
     index.html gave #player-names-modal, #games-library-modal and
     #game-record-modal an inline style="display:none". show*Modal() only
     added an .active class, which sets opacity and pointer-events but
     cannot override an inline display. The dialog never rendered: the mode
     dialog closed, nothing opened, and the player was left on Home.
     Not specific to "after Vs Computer" — it failed for EVERY mode on the
     FIRST attempt. The same attribute silently disabled the Games library
     and the record/replay viewer.
     Reproduced with real coordinate taps before repair.

RC2  generateLegalSetup corrupted the red army in 100% of games.
     The bomb/front-row swap resolved to an already-placed array index, so
     one piece object was written to two stations and one bomb was dropped.
     Measured against the old code: 2000/2000 red formations affected,
     0/2000 navy. Red is the computer's army in Vs Computer and Player 2's
     army in Classic, so every game had an illegal opposing formation.

RC3  Replay never replayed. Step/Play only incremented a text label.

RC4  Every app launch created and saved a junk game (constructor called
     startNewGame -> saveState). Against a 20-game cap this evicted real games.

RC5  AI information boundary leaked identity through the piece id
     ("navy-司令-0"); name and rank were redacted but id was not.

RC6  Movement did not match the drawn board: any adjacent step was legal, so
     pieces crossed the front line at columns 1 and 3 where no line exists;
     rows 0 and 11 were wrongly marked as railway.

RC7  Move animation often did not run — transition and transform were set in
     the same rAF callback, so the browser could coalesce them into a jump.

RC8  No session isolation: one long-lived board object, and AI timers that
     wrote into whatever game existed when they fired.

RC9  Service worker version skew — network-first HTML paired with
     stale-while-revalidate code could mix two builds.

RC10 Game-over "Home" called this.app.showSurface(), which does not exist.
